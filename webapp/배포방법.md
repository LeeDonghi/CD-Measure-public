# CD Measure 웹 버전 배포 방법

> **외부(인터넷) 배포 승인됨 (2026-07-31)** — 원래는 사내망 전용으로 설계했으나,
> 개인 PC를 사내 서버로 쓰려다 회사 네트워크의 클라이언트 격리 정책으로 실패해
> Oracle Cloud(개인 무료 계정)로 외부 배포하기로 결정함(사용자 명시적 승인,
> `프로젝트_설계문서.md` 8번 섹션 참고). **단, 외부에 열 때는 아래 2단계(Caddy로
> HTTPS)가 반드시 필요합니다** — 승인 여부와 무관하게 비밀번호가 암호화 없이
> 오가면 안 되기 때문. 사내망에서만 쓸 거면 1단계(`docker run`)만으로 충분합니다.

---

## 0. 준비

- **Docker**가 깔려 있고 실행 중이어야 합니다.
  - 윈도우: Docker Desktop 설치 후 실행(트레이 아이콘이 "Engine running")
  - 리눅스 서버: `docker` 서비스 실행 중
- **명령을 실행할 창을 새로 열어야 합니다.** Docker를 설치하기 *전에* 열어둔
  PowerShell/VS Code 터미널은 옛 PATH를 물고 있어서 `docker: command not found`가
  납니다. 창을 새로 여는 것만으로 해결됩니다.
- **프로젝트 최상위 폴더**(이 `webapp` 폴더의 부모)에서 빌드해야 합니다.
  웹 버전이 상위 폴더의 `ocr_core.py`, `char_templates.pkl` 등을 그대로
  쓰기 때문입니다.

## 1. 사내망 전용으로 쓸 때 (HTTPS 없이 간단히)

> 인터넷에 공개할 거면 이 방식 말고 **2번(Caddy로 HTTPS)**을 쓰세요.

### 1-A. 윈도우에서 (테스트용)

새 PowerShell 창을 열고 아래를 통째로 붙여넣습니다.

```powershell
cd "C:\Users\donghi.lee\Downloads\VS Code\CD Measure"

docker build -f webapp/Dockerfile -t cd-measure-web .

mkdir C:\cd-measure-data -Force

docker run -d -p 5000:5000 `
  -e CD_MEASURE_SECRET_KEY=$([guid]::NewGuid().ToString()+[guid]::NewGuid().ToString()) `
  -v "C:\cd-measure-data:/data" `
  --name cd-measure cd-measure-web
```

> PowerShell에서 줄을 나눌 때는 백틱(`` ` ``)을 씁니다. 한 줄로 붙여 써도 됩니다.
> (옛 명령프롬프트의 `^`를 쓰면 PowerShell에서는 깨집니다)

### 1-B. 리눅스 서버에서

```bash
cd /경로/CD-Measure

docker build -f webapp/Dockerfile -t cd-measure-web .

mkdir -p /srv/cd-measure-data

docker run -d -p 5000:5000 \
  -e CD_MEASURE_SECRET_KEY="$(openssl rand -hex 32)" \
  -v /srv/cd-measure-data:/data \
  --restart unless-stopped \
  --name cd-measure cd-measure-web
```

`--restart unless-stopped`를 붙이면 서버가 재부팅돼도 자동으로 다시 뜹니다.

## 2. 외부(인터넷) 배포용 — Caddy로 HTTPS 자동 처리

프로젝트 최상위에 있는 `docker-compose.yml` + `Caddyfile`을 씀. 웹앱 컨테이너와
Caddy(리버스 프록시)를 같이 띄우고, Caddy가 Let's Encrypt에서 인증서를 자동으로
받아오고 갱신까지 함(certbot 같은 걸 따로 설정할 필요 없음).

### 2-A. 무료 도메인 준비 (DuckDNS 예시)
Let's Encrypt는 "IP 주소"가 아니라 "도메인 이름"이 있어야 인증서를 내줍니다.
서버가 무료 인스턴스라 고정 도메인이 없으므로, 무료 동적 DNS를 씀:

1. https://www.duckdns.org 접속 → 구글/깃허브 계정 등으로 로그인
2. 원하는 서브도메인 입력(예: `cd-measure` → `cd-measure.duckdns.org`) → **add domain**
3. 그 도메인의 IP 칸에 **서버의 공인 IP**를 입력하고 저장

### 2-A-2. 서버에서 80/443 포트 열기 (Oracle Cloud는 **두 군데** 다 열어야 함)

⚠️ 여기서 막히는 사람이 아주 많음. 클라우드 콘솔에서 방화벽을 열어도 **서버 OS
안쪽 iptables가 따로 막고 있어서** 접속이 안 됩니다. 둘 다 열어야 합니다.

**① Oracle 콘솔 쪽 (Security List 인그레스 규칙)**
Networking → Virtual Cloud Networks → `cd-measure-vcn` → public 서브넷의
Security List → **Add Ingress Rules**:

| Source CIDR | 프로토콜/포트 | 용도 |
|---|---|---|
| `0.0.0.0/0` | TCP 80 | Let's Encrypt 인증서 발급 + http→https 리다이렉트 |
| `0.0.0.0/0` | TCP 443 | 실제 서비스 접속 |

(22번 SSH는 VCN 마법사가 만들 때 이미 열려 있음)

**② 서버 OS 쪽 (Ubuntu 이미지의 기본 iptables)**
Oracle의 Ubuntu 이미지는 기본 iptables가 22번 외의 인바운드를 다 막습니다.
SSH로 접속해서:

```bash
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo netfilter-persistent save     # 재부팅 후에도 유지되게 저장
```

**증상으로 구분하는 법**: 콘솔 규칙만 열고 iptables를 안 열면 브라우저가 계속
"연결 시간 초과"만 뜹니다(거부가 아니라 무응답). 이때는 iptables를 먼저 의심.

### 2-A-3. 스왑 메모리 만들기 (권장)

Ubuntu 기본 이미지에는 스왑이 없습니다. 사진을 많이 올려서 메모리가 순간적으로
모자라면 리눅스가 프로세스를 강제 종료(OOM Killer)하는데, 스왑이 있으면 느려질
뿐 죽지는 않습니다. 특히 작은 사양(1~2 OCPU/6GB 등)으로 인스턴스를 받았다면 필수:

```bash
sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # 재부팅 후에도 유지
```

### 2-B. 배포 명령

```bash
cd /경로/CD-Measure

# .env 파일 생성 (git에 안 올라감 - 비밀값이므로)
cat > .env << 'EOF'
CD_MEASURE_SECRET_KEY=여기에_긴_무작위_문자열
CD_MEASURE_DOMAIN=cd-measure.duckdns.org
EOF

mkdir -p data   # 계정/이력/업로드 데이터가 쌓일 폴더

docker compose up -d --build
```

첫 실행 시 Caddy가 Let's Encrypt에서 인증서를 받아오는 데 몇 초~십몇 초 걸릴 수
있습니다. `docker logs cd-measure-caddy`로 `certificate obtained successfully`
로그가 보이면 준비 완료.

### 2-C. 접속
```
https://cd-measure.duckdns.org
```
`http://`로 접속해도 Caddy가 자동으로 `https://`로 리다이렉트함.

### 2-D. 로컬에서 미리 테스트하기 (도메인 없이)
`.env`에 `CD_MEASURE_DOMAIN`을 안 넣으면 Caddy가 `localhost`로 자체 서명 인증서를
씀 — 실제 배포 전에 `https://localhost`로 전체 흐름(로그인~처리~다운로드)을
미리 검증할 수 있음(브라우저가 "안전하지 않음" 경고를 띄우는 게 정상 — 진짜
Let's Encrypt 인증서가 아니라 로컬 전용이라서 그럼).

## 3. 계정 만들기 (필수, 1·2 공통)

웹에 **회원가입 화면이 없습니다.** 아무나 계정을 만들 수 있으면 안 되고,
접근할 사람을 관리자가 직접 통제해야 하기 때문입니다. 아래처럼 서버에서
직접 만듭니다.

```bash
docker exec -it cd-measure python add_user.py add 아이디
```

비밀번호를 두 번 입력하면 끝입니다. 그 외 명령:

```bash
docker exec -it cd-measure python add_user.py list          # 계정 목록
docker exec -it cd-measure python add_user.py add 아이디     # 비밀번호 변경도 같은 명령
docker exec -it cd-measure python add_user.py remove 아이디  # 계정 삭제
```

계정이 하나도 없으면 아무도 로그인할 수 없으니, 실행 직후 반드시 하나 만드세요.

## 5. 알아둘 것

### `-v ...:/data`를 반드시 붙일 것
계정(`users.json`), 누적 `실행이력.csv`, 업로드한 사진과 결과 파일이 전부 이
폴더에 쌓입니다. **이걸 빼먹으면 컨테이너를 다시 만들 때(이미지 업데이트 등)
그 데이터가 전부 사라집니다.** 특히 `실행이력.csv`는 여러 Lot에 걸친 누적
데이터라 복구가 안 됩니다.

### `CD_MEASURE_SECRET_KEY`는 한 번 정한 값을 계속 쓸 것
로그인 세션(쿠키)을 위조로부터 지키는 값입니다. 컨테이너를 다시 만들 때 다른
값을 넣으면 **로그인해 있던 사람들이 전부 로그아웃**됩니다. 처음 만든 값을
따로 보관해두고 계속 쓰세요.

**이 값은 비밀값이므로 git에 커밋하지 마세요.** 서버의 환경변수나 사내 비밀
관리 방식으로 보관하세요.

### 사진이 아주 많을 때
처리 시간은 **사진 1장당 1초 남짓**입니다(실측: 77장 약 90초). 웹 서버
타임아웃은 15분으로 잡아뒀으니 사진 700장 정도까지는 여유가 있습니다. 그보다
많으면 `webapp/Dockerfile`의 `--timeout 900` 값을 늘리세요.

### 이미지를 업데이트할 때 (코드를 고친 뒤)

**1번(docker run) 방식이면:**
```bash
git pull                                            # 새 코드 받기
docker build -f webapp/Dockerfile -t cd-measure-web .
docker rm -f cd-measure                             # 기존 컨테이너 제거
# 위 1.의 docker run 명령을 다시 실행 (같은 -v, 같은 SECRET_KEY로!)
```

**2번(docker compose) 방식이면 훨씬 간단합니다:**
```bash
git pull
docker compose up -d --build   # 바뀐 부분만 알아서 다시 빌드하고 교체
```

`-v`/`./data`로 연결한 폴더는 그대로 남아 있으므로 계정과 이력은 유지됩니다.

## 6. 문제가 생겼을 때

```bash
docker ps                      # 컨테이너가 떠 있는지 (Up ... 이면 정상)
docker logs cd-measure         # 서버 로그 (오류 원인 확인)
docker logs -f cd-measure      # 실시간으로 보기
docker restart cd-measure      # 다시 시작
```

| 증상 | 원인/해결 |
|---|---|
| `docker: command not found` | Docker 설치 전에 열어둔 창임 → 창을 새로 열기 |
| `Cannot connect to the Docker daemon` | Docker Desktop(또는 docker 서비스)이 실행 중이 아님 |
| 로그인이 안 됨 | 계정을 안 만들었음 → 위 3. 참고 |
| 처리 중 페이지가 끊김 | 사진이 너무 많음 → `--timeout` 값 늘리기 |
| 재시작하니 로그인이 다 풀림 | `SECRET_KEY`가 매번 바뀌고 있음 → 고정값으로 지정 |
| 인증서 발급 실패(2번 방식) | DuckDNS의 IP가 서버 공인 IP와 다르거나, 80/443 포트가 방화벽에 막혀있음 → 위 2-A-2의 **두 군데(콘솔 Security List + 서버 iptables)** 다 열었는지 확인 |
| 브라우저가 "연결 시간 초과"만 뜸 (거부가 아니라 무응답) | 서버 OS의 iptables가 막고 있는 것 → 2-A-2의 ② |
| 인스턴스를 막 만들었는데 SSH가 안 됨 | 부트 볼륨 초기화에 최대 5분 걸림. **지우고 다시 만들지 말 것** — 지우는 순간 그 재고는 다른 사람이 가져감 |
| 로그인은 되는데 로그인 잠금이 접속자 전체에 걸림 | `CD_MEASURE_TRUST_PROXY=1`이 안 켜져서 모든 접속자가 Caddy의 IP 하나로 보임 - `docker-compose.yml`에 이미 설정돼 있으니 compose로 띄웠는지 확인 |

## 7. 검증 이력

### 2026-07-30 (1번 방식, `docker run`)
- 이미지 빌드 성공(696MB), 컨테이너 안에서 `tkinter` import 정상
  (`python:3.12-slim`에는 tkinter가 없어서 `python3-tk`를 apt로 넣는 우회를 씀)
- gunicorn 워커 2개로 기동, 로그인 페이지 정상
- 브라우저로 로그인 → `samples/Sample` 사진 77장 업로드 → 처리 → 엑셀
  다운로드까지 완주. Cpk 결과가 데스크탑 버전과 동일
  (`5.5 Space=5.3923 / 9.5 Line=9.4154 / 14.5 Pad CD=14.9538`)
- 컨테이너를 완전히 삭제하고 새로 만든 뒤에도 계정·실행이력·지난 결과 유지

### 2026-07-31 (2번 방식, `docker compose` + Caddy)
- `CD_MEASURE_DOMAIN` 없이(로컬 테스트) `docker compose up -d --build` 성공,
  Caddy가 `localhost`용 자체 서명 인증서를 자동 발급(`certificate obtained
  successfully` 로그 확인)
- `http://localhost` → 308로 `https://localhost` 자동 리다이렉트 확인
- 브라우저(Playwright)로 `https://localhost`에서 로그인 성공, 리다이렉트 후에도
  `https` 스킴 유지 확인(`ProxyFix(x_for=1, x_proto=1)` 정상 동작)
- 실제 도메인(DuckDNS)으로 Let's Encrypt 인증서를 발급받는 것과, 로그인 잠금이
  Caddy 뒤에서도 접속자별로 정확히 구분되는지는 **아직 실서버 미검증**
  (Oracle 인스턴스 생성 대기 중이라 로컬 검증까지만 완료).
